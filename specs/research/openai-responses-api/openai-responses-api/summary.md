# OpenAI Responses API

## Bottom Line

OpenAI documents the rule behind Kiln's workaround in one sentence: "Starting with GPT-5.4, Chat Completions does not support tool calling with `reasoning_effort` values other than `none`." For GPT-6 Astra, GPT-6.1 Sol and GPT-6.1 Terra, Chat Completions does not support tool calling at all. OpenAI support has said it has not "confirmed a fix", so this is policy, not a bug. Moving to `/v1/responses` changes almost every wire shape Kiln touches: `input` items instead of `messages`, flat function tools that default to *attempting* strict mode, `function_call` / `function_call_output` items linked by `call_id`, `text.format` (whose `strict` defaults to `false`), typed streaming events, and different usage field names. Two defaults need deliberate handling: Responses stores every response for at least 30 days unless `store: false` is sent, and reasoning continuity in a stateless tool loop needs each reasoning item replayed with its `encrypted_content`. Replaying a reasoning item by id without that content under `store: false` fails with "Item with id 'rs_...' not found". Chat Completions is still supported and not deprecated, but OpenAI recommends Responses for all new work. Every model generation since GPT-5.4 has added features that only work on Responses.

## Key Findings

- **The rule and the error.** Migration guide: "Starting with GPT-5.4, Chat Completions does not support tool calling with `reasoning_effort` values other than `none`." Error (HTTP 400, `param: reasoning_effort`): "Function tools with reasoning_effort are not supported for gpt-5.6-sol in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'." — [migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses), [Microsoft Learn](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/reasoning), [community thread with OpenAI support reply 2026-09-07](https://community.openai.com/t/gpt-5-6-chat-completion-reasoning-effort-bug-behavior-change/1386454). Details: [models-and-endpoint-support.md](./models-and-endpoint-support.md)
- **Per-model limits.** GPT-6 Astra, GPT-6.1 Sol and GPT-6.1 Terra cannot use tools on Chat Completions at all. GPT-6 Sol, GPT-6 Luna, GPT-5.6 Sol/Terra/Luna, GPT-5.5 and GPT-5.4 can only with `none`. GPT-5.2 Pro, GPT-5.4 Pro and GPT-5.5 Pro are Responses-only models. GPT-6 Astra returns 400 for `none`; GPT-6.1 Sol rejects `none` and `minimal`. — [Using GPT-6](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra), model pages
- **Function tools.** Responses tools are flat (`{"type": "function", "name", "description", "parameters", "strict"}`). "In Responses, omitting `strict` attempts strict mode; if the schema cannot be made compatible, Responses falls back to non-strict... To keep non-strict behavior in Responses explicitly, set `strict: false`." Chat Completions defaults to non-strict. — [function calling guide](https://developers.openai.com/api/docs/guides/function-calling)
- **Tool calls and results.** Output items are `{"type": "function_call", "id": "fc_...", "call_id": "call_...", "name", "arguments"}`. Results go back as `{"type": "function_call_output", "call_id", "output"}`, with `call_id` max 64 chars. Reasoning items returned with tool calls "must also be passed back". — [function calling guide](https://developers.openai.com/api/docs/guides/function-calling), [API reference](https://developers.openai.com/api/reference/resources/responses/methods/create)
- **Structured output.** It moves from `response_format` to `text.format` with a flat `{type: "json_schema", name, schema, strict}`. The reference gives `strict` a default of `false`, the opposite of the tools default. — [API reference](https://developers.openai.com/api/reference/resources/responses/methods/create)
- **Reasoning items and `store: false`.** "When you create a response in stateless mode, reasoning items... include an `encrypted_content` property by default... The API still accepts the legacy `reasoning.encrypted_content` value in `include`." This default appears to date from about mid-July 2026. Replaying a reasoning item by `id` without content under `store: false` returns "Item with id 'rs_...' not found. Items are not persisted when `store` is set to false". OpenAI-direct accepts `id` plus `encrypted_content`. Third-party reports say Azure rejects that combination too. — [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning), [openai/codex #35739](https://github.com/openai/codex/issues/35739). Details: [reasoning-and-state.md](./reasoning-and-state.md)
- **Use the final encrypted reasoning when streaming.** "When streaming, use the completed reasoning item and its `encrypted_content` from the `response.output_item.done` event... The `encrypted_content` in `response.output_item.added` may be incomplete." — [API reference](https://developers.openai.com/api/reference/resources/responses/methods/create)
- **Persisted reasoning and `phase`.** GPT-5.6 models default to `reasoning.context: "all_turns"` and use earlier-turn reasoning when it is replayed. On GPT-5.4 and later, assistant messages should keep their `phase` (`commentary` / `final_answer`), or "preambles [can] be treated as final answers". Kiln's chat-format trace carries neither, so both need an extension or will be lost (inference). — [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning)
- **Reasoning summaries are Responses-only.** Set `reasoning.summary: "auto"`. Summaries arrive as `summary[]` parts on reasoning items and stream as `response.reasoning_summary_text.delta` with `output_index` plus `summary_index`. Neither index is a choice index. Org verification may be required. The Chat Completions reference has no summary field. — [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning), [streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events). Details: [streaming.md](./streaming.md)
- **Streaming is typed events.** Text arrives as `response.output_text.delta`. A tool call's name and `call_id` arrive only on `response.output_item.added`, and argument deltas are keyed by `output_index`, which counts every item including reasoning. Usage arrives only on `response.completed`. A stream can also end with `response.incomplete` or `response.failed`, and an `error` event can come mid-stream. OpenAI may add new event types at any time. — [streaming guide](https://developers.openai.com/api/docs/guides/streaming-responses), [openai-python event union](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_stream_event.py)
- **Parameters that are gone or moved.** These have no Responses equivalent: `n` ("returns only one generation"), `stop`, `seed`, `frequency_penalty`, `presence_penalty`, `logit_bias`, `prediction`, and audio. Logprobs move to `include: ["message.output_text.logprobs"]` plus `top_logprobs`. `max_completion_tokens` becomes `max_output_tokens` (minimum 16). `temperature`, `top_p` and logprobs are rejected unless effort is `none`, on both endpoints. — [request-response-shape.md](./request-response-shape.md)
- **`store` and retention.** Responses defaults to `store: true`: "response data will be stored for at least 30 days", visible in dashboard logs. The Chat Completions reference says `store` defaults to `false`, while the migration guide says Chat Completions are "stored by default for new accounts". ZDR forces `store` false on both endpoints. The Conversations API keeps data "Until deleted" and is not ZDR-eligible. `previous_response_id` needs stored responses and still bills every prior input token. — [Data controls](https://developers.openai.com/api/docs/guides/your-data). Details: [data-retention-caching-pricing.md](./data-retention-caching-pricing.md)
- **Caching and pricing.** Token prices are listed per model, not per endpoint. OpenAI claims 40–80% better cache utilization on Responses ("internal tests") and a 3% SWE-bench gain for reasoning models. GPT-5.6 and later bill cache writes at 1.25× input (2.5× for a 12h lifetime "in the Responses API") and reads at 0.1×, or 0.05× on GPT-6.1 Sol and Terra. — [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)
- **Features that only work on Responses.** Tools with reasoning on GPT-5.4 and later; Pro models; pro mode (`reasoning.mode`); reasoning summaries; passing CoT and encrypted reasoning; `reasoning.context`; `phase`; `configuration_update`; built-in tools; `previous_response_id` and Conversations. **Not** Responses-only: `max` effort (it is in the Chat Completions `reasoning_effort` enum), structured outputs, custom tools, prompt-cache breakpoints. — [models-and-endpoint-support.md](./models-and-endpoint-support.md)
- **Future of Chat Completions.** "While Chat Completions remains supported, Responses is recommended for all new projects." The Deprecations page lists no deprecation. The API Overview's "choose the API surface" step doesn't mention Chat Completions.
- **New failure mode on GPT-6 Astra.** Misalignment monitoring can block Responses requests that use persisted reasoning. It returns HTTP 403 with code `misalignment_policy_violation`, possibly mid-stream. Chat Completions requests are "Not covered". — [Misalignment monitoring](https://developers.openai.com/api/docs/guides/safety-checks/misalignment-monitoring)
- **OpenRouter.** Kiln's OpenRouter Chat Completions route works for these models. Its docs strongly imply it converts OpenAI requests to Responses upstream: reasoning formats are tagged `openai-responses-v1`, and "a Chat Completions... update sent to an OpenAI model becomes a Responses `configuration_update` item". Its own Responses API rejects `store: true` and `previous_response_id`. — [openrouter-and-azure.md](./openrouter-and-azure.md)
- **Azure.** Azure supports Responses on the v1 API (`/openai/v1/responses`) for the same model families. It has the same Chat Completions tools-with-reasoning error and the same encrypted-by-default behavior. Stored responses are kept 30 days. — [Microsoft Learn](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/responses)

## Open Questions / Gaps

- **No live verification.** No API key was used. Every behavior here comes from docs or third-party reports, not from calls I made.
- **Chat Completions `store` default.** The reference says `false`; the migration guide says new accounts store by default. I could not resolve this.
- **Omitting `reasoning_effort` with tools on Chat Completions.** On GPT-5.5 and GPT-5.6, where the default effort is `medium`, it is unclear whether this triggers the 400. Third-party sources contradict each other (ObjectGraph and LangChain say yes; APIYI says no) and OpenAI's docs are silent.
- **GPT-5.4 mini and nano.** OpenAI never says per model whether the GPT-5.4 rule covers them. Their model pages are silent.
- **Why Kiln hides `max` on GPT-6.1 Sol.** I found no OpenAI restriction that explains it. The Chat Completions reference accepts `max`, and the GPT-6.1 Sol page lists `max`.
- **Azure rejecting `id` + `encrypted_content` under `store: false`.** This rests on one detailed Codex issue (2026-07-28) and an older one. No Microsoft statement.
- **`encrypted_content` with `store: true`.** It is apparently returned there too, per a community reply, but this is undocumented and there is no documented way to suppress it.
- **12h cache lifetime.** The caching guide says it is Responses-only. Both references describe `prompt_cache_options.ttl` as `"30m"` only, while `prompt_cache_breakpoint.ttl` accepts `"12h"` on both endpoints.
- **`reasoning.context: all_turns` model list.** OpenAI names GPT-5.6 and GPT-6.1 Sol; Microsoft adds GPT-5.4 and GPT-5.5.
- **Streaming events reference.** The page is too large to fetch whole, so event fields come from targeted extracts, guides, and the openai-python generated types. I did not read every event's full schema.
- **OpenRouter's upstream endpoint for OpenAI models.** This is inferred from its docs, not stated. Its `debug.echo_upstream_body` flag (streaming only) would confirm it.
- **"40–80% better cache utilization".** OpenAI publishes no method or dataset for this claim.
