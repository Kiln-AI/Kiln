# Architecture: Split eval traces from eval scores

Implements [`functional_spec.md`](functional_spec.md). Decisions D1–D21 live in
[`research.md`](research.md) §5.

Built on `claude/eval-splits-evals-v2` — `Eval.splits`, `resolve_split()`, `ItemKey` and
`eval_run_item_key()` are reused, never reimplemented.

## 1. Data model

### 1.1 `EvalItemSource` — new, in `datamodel/task_run.py`

```python
class EvalItemSource(BaseModel):
    """The eval dataset item a TaskRun was generated for.

    Not the run config — that lives on the same TaskRun at
    `output.source.run_config_id`.
    """
    source_type: Literal["eval_input", "task_run"]
    source_id: ID_TYPE
```

**Defined in `task_run.py`, not `eval.py`.** `eval.py` already imports `TaskRun` under
`TYPE_CHECKING` only; putting this type in `eval.py` and referencing it from `TaskRun`
would create a real (non-`TYPE_CHECKING`) import cycle. `eval_splits.py` imports it to
build an `ItemKey`; that direction is already established.

Helper on the module, mirroring `eval_run_item_key()`:

```python
def eval_item_key(source: EvalItemSource) -> ItemKey:
    return (source.source_type, source.source_id)
```

### 1.2 `TaskRun` — one field

```python
eval_source: EvalItemSource | None = Field(
    default=None,
    description="Set when this run was generated by an eval. Names the eval dataset "
                "item it was generated for. None for ordinary dataset runs.",
)
```

No validators added. Presence is the eval-generated flag (functional spec §3.1).

### 1.3 `TaskRun` accessor — `Task.runs()`

```python
def runs(self, readonly: bool = False,
         include_intermediate_runs: bool = False,
         include_eval_generated: bool = False) -> list[TaskRun]:
```

Filter applied after the existing leaf filter:

```python
if not include_eval_generated:
    raw = [r for r in raw if r.eval_source is None]
```

Order matters only for cost, not correctness; both are in-memory list filters over the
already-loaded set.

### 1.4 `EvalRun` — one field added, six deprecated

```python
scored_run_id: ID_TYPE | None = Field(
    default=None,
    description="The TaskRun this score was computed over. None for legacy records "
                "that carry their trace inline.",
)

eval_usage: Usage | None = Field(
    default=None,
    description="The usage of the evaluation model (judge) that produced this eval run's scores, aggregated across every LLM call the judgment made. Distinct from task_run_usage, which is the evaluated task run's usage. None for non-LLM evals (e.g. code evals) and for records that predate this field.",
)
```

`input` changes from `str` to `str | None = None`.

Deprecated — kept declared, never set on new records: `input`, `output`,
`task_run_trace`, `task_run_usage`, `reference_answer`. Mark each with a
`DEPRECATED:` prefix in its `description` so the deprecation reaches the generated
OpenAPI schema and the web types.

### 1.5 `EvalRun` validators

**New — `validate_record_mode`** (functional spec §3.3):

```python
LEGACY_TRACE_FIELDS = ("output", "task_run_trace", "task_run_usage", "reference_answer")

@model_validator(mode="after")
def validate_record_mode(self) -> Self:
    inline_set = [f for f in LEGACY_TRACE_FIELDS if getattr(self, f) is not None]

    if self.scored_run_id is not None:
        if self.input is not None or inline_set:
            raise ValueError(
                "An EvalRun with scored_run_id must not carry inline trace data "
                f"(set: {['input'] if self.input is not None else []} {inline_set}). "
                "The trace lives on the referenced TaskRun."
            )
        return self

    if self.skipped_reason is not None:
        return self          # skipped before generation: nothing to point at

    if self.input is None:
        raise ValueError(
            "A legacy EvalRun (no scored_run_id) requires input."
        )
    return self
```

Ordering note: the skip branch is checked *after* the pointer branch so a
skipped-at-scoring-time record (which has a `scored_run_id`) still gets the
no-inline-data check.

**Changed — `validate_output_fields`.** Its "V1 EvalRun requires output" rule must not
fire for pointer-mode records. Add an early return when `scored_run_id is not None`,
alongside the existing V2 bypass.

**Unchanged:** `validate_scores`, `validate_input_source`, `validate_eval_run_types`,
`validate_reference_answer`.

## 2. The core technical problem: trace lookup

### 2.1 Why the existing pattern does not work

`collect_tasks()` precomputes `already_run` before any job executes. A trace persisted
during the run is invisible to it. That breaks two things the spec requires:

- **Retry** (§4.3) — a retry after a scoring failure would regenerate.
- **Concurrency** — `AsyncJobRunner` runs 25 jobs at once. Two jobs sharing an
  `(item, run_config)` but differing in `eval_config` both miss and both generate,
  wasting exactly the money this project exists to save.

The second is the sharper problem, and it is *new*: today the eval_config is part of the
key, so those two jobs were never meant to share.

### 2.2 `TraceIndex` — new, in `adapters/eval/trace_index.py`

Runner-owned. Seeded once, kept live, with per-key locking.

```python
TraceKey = tuple[str, ID_TYPE, ID_TYPE]   # (source_type, source_id, run_config_id)


class TraceIndex:
    def __init__(self, task: Task):
        self._task = task
        self._paths: dict[TraceKey, Path] = {}
        self._key_locks: dict[TraceKey, asyncio.Lock] = {}
        self._registry_lock = asyncio.Lock()
        self._seed()

    def _seed(self) -> None:
        for run in self._task.runs(readonly=True, include_eval_generated=True):
            if run.eval_source is None or run.path is None:
                continue
            rc_id = run.output.source.run_config_id if run.output.source else None
            if rc_id is None:
                continue
            key = (run.eval_source.source_type, run.eval_source.source_id, rc_id)
            self._paths.setdefault(key, run.path)      # D8: first wins

    async def get_or_create(
        self, key: TraceKey, generate: Callable[[], Awaitable[TaskRun]]
    ) -> tuple[TaskRun, bool]:
        """Returns (trace, was_generated). `generate` must persist the TaskRun."""
        async with self._registry_lock:
            lock = self._key_locks.setdefault(key, asyncio.Lock())

        async with lock:
            path = self._paths.get(key)
            if path is not None:
                return TaskRun.load_from_file(path), False
            run = await generate()
            if run.path is None:
                raise ValueError("generate() must persist the TaskRun before returning")
            self._paths[key] = run.path
            return run, True
```

**Design notes:**

- **Paths, not objects.** Holding every eval trace in memory is unacceptable at the
  scale this project creates (traces are the large field). `ModelCache` already makes
  repeat `load_from_file` cheap, keyed on path + mtime.
- **Two-level locking.** `_registry_lock` guards only lock *creation*, so it is held for
  nanoseconds. The per-key lock is held across generation, which serializes only jobs
  that would otherwise duplicate work. Jobs on different keys never contend.
- **The seed is not an extra scan.** `collect_tasks` already walks `task.runs()`. Build
  the index from the same pass.
- **`setdefault` on seed** implements D8's "first wins" for duplicate traces from sync.
- **`generate` persists before returning**, satisfying functional spec §4.1 step 1: the
  trace is durable before scoring is attempted.

### 2.3 The score-level check stays precomputed

Only the *trace* lookup needs to be live. The "already scored" check remains in
`collect_tasks()`, unchanged.

This works because `EvalRun` keeps its denormalized `dataset_id` / `eval_input_id` and
`task_run_config_id` (D13). At collect time we do not yet know which TaskRun a job will
resolve to — but we do not need to: "has this `(eval_config, run_config, item)` been
scored?" is answerable from fields already on the record. Every job is unique in that
triple, so no job can create a score another job in the same run is also checking.

This is the payoff of denormalizing the `ItemKey` onto the score record: the existing
`already_run` machinery keeps working, and the new live index is scoped to one concern.

## 3. Runner changes — `adapters/eval/eval_runner.py`

### 3.1 Construction

`EvalRunner.__init__` builds `self._trace_index = TraceIndex(self.task)`.

### 3.2 `_run_v2_job` restructured

Today's method branches five ways over `(item type, job type)` and writes an `EvalRun`
in each branch. It collapses to one path:

```python
async def _run_v2_job(self, job: EvalJob) -> bool:
    evaluator, skip = self._resolve_adapter(job)      # NotImplementedError -> skip record
    if skip:
        return await self._persist_skip(job, skip)

    if self._is_multi_turn(job.item):
        return await self._persist_skip(job, SKIP_MULTI_TURN)

    trace, _generated = await self._resolve_trace(job)   # calibration returns the item itself
    result = await evaluator.evaluate(EvalTaskInput.from_task_run(trace, job.item))
    return await self._persist_eval_run(job, trace, result)
```

`_resolve_trace`:

```python
async def _resolve_trace(self, job: EvalJob) -> tuple[TaskRun, bool]:
    if job.type == "eval_config_eval":
        # Calibration: the scored run IS the golden dataset item. Nothing generated,
        # nothing flagged, nothing indexed.
        assert isinstance(job.item, TaskRun)
        return job.item, False

    key = (*item_key(job.item), job.task_run_config.id)
    return await self._trace_index.get_or_create(
        key, lambda: self._generate_and_persist(job)
    )
```

`_generate_and_persist` calls `evaluator.run_task(job.item)`, stamps
`eval_source=EvalItemSource(...)`, and saves inside `self._save_context()` — the run's
`output.source.run_config_id` is already set by the adapter.

**`run_task` must now persist.** Today it deliberately does not
(`eval_runner.py:498-499`), to avoid polluting the dataset. Default-exclude (§1.3) is the
replacement for that protection.

### 3.3 `EvalTaskInput` assembly

`EvalTaskInput.from_eval_input(eval_input, run_output)` and `.from_task_run(task_run)`
both survive. The unified path needs one accessor that takes the trace plus the source
item (for `reference_data`), so add:

```python
@classmethod
def from_trace(cls, trace: TaskRun, source: TaskRun | EvalInput) -> "EvalTaskInput"
```

The two existing constructors become thin wrappers, kept for their current callers.

### 3.4 What is deleted

The five inline `EvalRun(...)` constructions in `_run_v2_job` collapse to two helpers
(`_persist_skip`, `_persist_eval_run`). `_run_legacy_job` is untouched — V1 configs keep
writing inline-mode records, which remains a valid state.

### 4.1 Packaging — needs an explicit decision

`export_task_runs` (`package_project.py:978`) is a `shutil.copytree` of `runs/`, so it
copies eval traces by construction — a field-level filter is invisible to it. The
existing `exclude_eval_config_runs` flag has an `ignore_fn` hook
(`_ignore_eval_config_runs`) that filters by path, which cannot see `eval_source`.

**Decision:** when `exclude_eval_config_runs=True`, also skip eval-generated TaskRuns,
by parsing each `task_run.kiln` in the `ignore_fn`. This is slow per file, but it is an
explicit opt-in flag on an export operation, not a hot path, and the flag exists
precisely to keep eval data out of packages. With the flag off, behavior is unchanged
(everything is copied), which is the conservative default.

## 5. API changes — `app/desktop/studio_server/eval_api.py`

### 5.1 Joined view model

`EvalRunResult.results` changes from `List[EvalRun]` to `List[EvalRunWithTrace]`:

```python
class EvalRunWithTrace(BaseModel):
    """An EvalRun plus the trace fields resolved from its scored TaskRun.

    Legacy inline records populate these from their own fields; pointer records
    from the referenced TaskRun. The frontend sees one shape.
    """
    eval_run: EvalRun
    input: str | None
    output: str | None
    task_run_trace: str | None
    task_run_usage: Usage | None
```

Resolution, per record:

- `scored_run_id is None` → read the EvalRun's own inline fields.
- `scored_run_id` set → load the TaskRun; use `input`, `output.output` (**never
  `repaired_output`** — functional spec §5.2), `trace`, `usage`.
- TaskRun missing → all four `None`. The score still renders (§5.3).

The endpoint loads referenced TaskRuns with `Task.from_ids_and_parent_path` — the
existing bulk accessor, which scans the directory once instead of per-id.

### 5.2 Usage rollup

`get_eval_run_run_config_summary` (`eval_api.py:1862-1878`) reads usage from the
resolved trace rather than `eval_run.task_run_usage`:

```python
usage = trace.usage if trace is not None else eval_run.task_run_usage
```

`TaskRun.usage`, not `cumulative_usage` — it already accumulates across every LLM call
(`litellm_adapter.py:163,308`) and, unlike `MessageUsage`, carries
`total_llm_latency_ms`, which this summary reports.

### 5.3 Untouched

`compute_score_summary`, `get_eval_configs_score_summary`, and all completeness math read
only fields that remain on `EvalRun`. No changes.

### 5.4 Schema

`api_schema.d.ts` regenerates. `check_schema.sh` must pass.

## 6. Delete protection — `libs/server/kiln_server/run_api.py`

Both `delete_run` (`:240`) and `delete_runs` (`:368`, bulk) gain the same guard:

```python
if run.eval_source is not None:
    raise HTTPException(
        status_code=409,
        detail="This run can't be deleted because it's needed for an eval.",
    )
```

409 rather than 400: the request is well-formed, the resource state forbids it.

For the bulk endpoint, eval-generated runs are **reported, not silently skipped** — the
existing per-run error collection carries the reason back, so the user learns why a
selection was partially deleted.

No reverse reference scan (D16): the flag on the TaskRun is sufficient and holds whether
or not an EvalRun currently points at it.

## 7. Migration — `libs/core/kiln_ai/cli/commands/` (final phase)

A one-shot CLI command, `migrate-eval-runs`, over one project directory.

```
for eval in task.evals():
  for config in eval.configs():
    if config.config_type != v2: continue          # V1 untouched
    for eval_run in config.runs():
      if eval_run.scored_run_id is not None: continue        # idempotent
      if eval_run.eval_config_eval:                          # calibration
          eval_run.scored_run_id = eval_run.dataset_id
      elif eval_run.skipped_reason is not None and eval_run.output is None:
          pass                                               # skip, no trace
      else:
          trace = TaskRun(parent=task, ... from inline fields ...)
          trace.save_to_file()
          eval_run.scored_run_id = trace.id
      clear inline fields; eval_run.save_to_file()
```

- **One TaskRun per EvalRun, no grouping** (functional spec §8). Duplicate traces across
  eval configs are accepted for this one internal dataset.
- **Idempotent** — a pointer-mode record is skipped.
- **Dry-run flag** printing counts per category before writing.
- **Order:** save the TaskRun before rewriting the EvalRun, so an interrupted run leaves
  an orphan TaskRun (harmless, invisible by default) rather than a dangling pointer.
- `input_source` on the synthesized TaskRun is `synthetic` with the run config from
  `task_run_config_id`.

## 8. Error handling

| Failure | Behavior |
|---|---|
| Generation raises | Nothing persisted (D14). Job errors; `AsyncJobRunner` retries per its existing policy. Item reads as incomplete |
| Scoring raises after generation | Trace already durable. Job errors and retries; the retry hits the index, skips generation, re-scores |
| Adapter unavailable / multi-turn / reference-key missing | Skip record, as today |
| `scored_run_id` dangles | Read paths degrade to `None` trace fields; score still renders and still counts in aggregation. Never raises, never cascades |
| Two workers race on one trace key | Per-key lock serializes; the loser reuses the winner's trace |
| Trace persisted but process dies before the score | Next run finds the trace, skips generation, scores. This is the second project goal working |

Logging: one `debug` per trace-index hit (key + reused run id); one `info` per generated
trace. No new user-facing error surfaces beyond the 409.

## 9. Testing

### 9.1 Datamodel (`libs/core/kiln_ai/datamodel/test_eval_model.py`)

- `validate_record_mode`: pointer + `input` set → raises; pointer + each of the four
  trace fields → raises; legacy without `input` → raises; legacy with `input` → valid;
  skipped without `scored_run_id` → valid; skipped with `scored_run_id` and no inline
  data → valid.
- Every V1 fixture on disk still loads unchanged (regression guard for D15).
- `validate_output_fields` early-returns for pointer records.
- `Task.runs()`: eval-generated excluded by default; included with the flag; interaction
  with `include_intermediate_runs` (both filters compose).

### 9.2 `TraceIndex` (`libs/core/kiln_ai/adapters/eval/test_trace_index.py`) — new

- Seed finds an existing eval-generated run and returns it without calling `generate`.
- Seed ignores runs with `eval_source is None`.
- Duplicate seed entries: first wins (D8).
- **Concurrency:** 25 concurrent `get_or_create` on one key call `generate` exactly once,
  and all callers get the same run. This is the test that protects the money.
- Different keys generate concurrently — assert no serialization (the per-key lock does
  not become a global one).
- `generate` returning an unsaved run raises.

### 9.3 Runner (`test_eval_runner.py`)

- **The headline test:** run an eval, add a second eval config, run again — assert
  `run_task` is called zero times on the second run and a second set of EvalRuns exists.
- Calibration creates no TaskRun and sets `scored_run_id = dataset_id`.
- Scoring failure leaves the trace persisted; a retry regenerates nothing.
- Trace carries `eval_source` matching the item's `ItemKey`.
- V1 legacy job path unchanged (characterization).

### 9.4 API (`test_eval_api.py`)

- `EvalRunWithTrace` resolves pointer records from the TaskRun and legacy records from
  inline fields, producing the same shape.
- `output`, not `repaired_output`, is returned when the TaskRun has both.
- Dangling `scored_run_id` → nulls, HTTP 200.
- Usage rollup reads `TaskRun.usage` for pointer records, `task_run_usage` for legacy.
- `compute_score_summary` characterization: unchanged output for unchanged input.

### 9.5 Delete protection (`test_run_api.py`)

- Deleting an eval-generated run → 409.
- Bulk delete with a mix → non-eval runs deleted, eval runs reported with reason.

### 9.6 Migration

- Fixture project with V1 records, V2 pointer records, V2 inline records, calibration
  records, and skip records → only V2 inline records change.
- Idempotent: second run is a no-op.
- Dry-run writes nothing.

## 10. Sequencing note

This is one coherent change across ~8 files, not a set of independently complex
components — so this single architecture doc replaces per-component designs.

The one ordering constraint: `Task.runs()` default-exclude (§1.3) must land **before**
`run_task` starts persisting (§3.2). Landing them in the other order pollutes every
dataset surface in between.
