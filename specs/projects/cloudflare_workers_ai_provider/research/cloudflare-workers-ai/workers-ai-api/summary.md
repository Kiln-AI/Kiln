# Workers AI API, Auth and LiteLLM Support

## Bottom Line

Kiln should call Workers AI via the OpenAI-compatible endpoint `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1/chat/completions` using LiteLLM's `openai/` provider with a custom base URL, the same pattern Kiln uses for SiliconFlow. LiteLLM's `cloudflare/` provider in Kiln's pinned version (1.87.x) is the old `/ai/run` implementation. It supports only `stream` and `max_tokens`, silently drops everything else, and returns empty text on newer models. LiteLLM rewrote it onto `/ai/v1` in 1.91.0 (July 2026), so it becomes an option after a LiteLLM upgrade.

Credentials are two values, an API token and a 32-hex account ID, and the account ID is part of every URL. There is no documented single-credential option. The best "Connect" check is `GET /accounts/{account_id}/ai/models/search?per_page=1`: it's free, checks token + account + Workers AI permission together, and works for both user and account tokens. The live test found `per_page` is ignored; Kiln's check uses `search=kiln-connection-check` instead, which returns an empty result ([live test findings](../../../live_test_findings.md)).

Feature support varies by model generation. Newer models look like OpenAI (tools, JSON schema, logprobs, `reasoning_effort`). Older ones are rougher: 256-token default output, no logprobs, bare-schema JSON mode, spotty tool calling on `/v1`. Reasoning output uses three different field conventions.

## Key Findings

- **Two endpoints, `/v1` is the one to use.** Native `/ai/run/{model}` returns different response shapes per model generation. `/ai/v1/chat/completions` (plus `/v1/embeddings`, and `/v1/responses` for GPT-OSS only) gives one OpenAI shape. Cloudflare fixed several `/v1` tool-calling bugs in Feb 2026. There is no `GET /ai/v1/models`; it returns 405, code 7001. — [OpenAI compat docs](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/), [peaproxy#45](https://github.com/ks1686/peaproxy/issues/45)
- **Auth = Bearer API token + account ID in path.** The Workers AI dashboard template creates a token with `Workers AI Read` + `Edit`. The OpenAPI spec accepts either one for inference. Account tokens (`cfat_`) and user tokens (`cfut_`) both work. Deriving the account ID from the token is unreliable, because listing accounts needs extra permissions (inferred, not tested). — [REST get-started](https://developers.cloudflare.com/workers-ai/get-started/rest-api/), [token formats](https://developers.cloudflare.com/fundamentals/api/get-started/token-formats/)
- **Don't validate with `/user/tokens/verify`.** It rejects valid account-owned tokens with code 1000 "Invalid API Token", and it doesn't check Workers AI permission. Use `GET /accounts/{id}/ai/models/search?per_page=1` instead. The live test found `per_page` is ignored; Kiln's check uses `search=kiln-connection-check` instead, which returns an empty result ([live test findings](../../../live_test_findings.md)). — [noorinalabs-deploy#511](https://github.com/noorinalabs/noorinalabs-deploy/issues/511), [Model Search API](https://developers.cloudflare.com/api/resources/ai/subresources/models/methods/list/)
- **Error signals for Connect.** Observed in the live test ([live test findings](../../../live_test_findings.md#connect-validation)): a malformed account ID gives 404, code 7003 "Could not route to ... perhaps your object identifier is invalid?". An invalid token gives 401/10000 and a junk token 400/9106. A well-formed account ID the token can't access gives 403/10000 on search, so "wrong token" and "wrong account" can't be fully told apart. A Workers Free account calling a paid-only model gives 403, code 5035. Still inferred: the response for a token without Workers AI permission. — [opencode#18552](https://github.com/anomalyco/opencode/issues/18552), [errors](https://developers.cloudflare.com/workers-ai/platform/errors/)
- **LiteLLM `cloudflare/` provider history.** Up to 1.90.x it calls `/ai/run`, supports only `["stream","max_tokens"]`, estimates tokens locally, and reads the account ID only from the `CLOUDFLARE_ACCOUNT_ID` env var ([litellm#24065](https://github.com/BerriAI/litellm/issues/24065): `KeyError: 'response'` on Nemotron). From 1.91.0 it's `CloudflareChatConfig(OpenAIGPTConfig)` on `/ai/v1`, using env vars `CLOUDFLARE_API_KEY`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_BASE`. Still no per-call account-ID param, so pass `api_base`. — [PR #31053](https://github.com/BerriAI/litellm/pull/31053)
- **LiteLLM `openai/` on 1.87.1 handles Workers AI's reasoning fields.** It reads `reasoning_content`, then `reasoning`, then `<think>` tags. When streaming, it maps `delta.reasoning` to `reasoning_content`. — installed LiteLLM source
- **Structured output.** `response_format` with `json_object` / `json_schema` is supported on most models. OpenAI-shape models take the `{name, schema, strict}` envelope. Legacy models document a bare schema, and whether `/v1` unwraps the envelope for them is **untested**. It's not guaranteed: the model can return "JSON Mode couldn't be met". **JSON mode doesn't support streaming.** — [JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/)
- **Tool calling is labeled Beta.** The `function_calling` flag is per model. One third party reports Llama 3.3 70B doesn't emit tool calls on `/v1` while GPT-OSS does. `tool_choice` and `parallel_tool_calls` exist only on newer models. — [function calling](https://developers.cloudflare.com/workers-ai/features/function-calling/), [laravel-cf-workersai](https://github.com/meirdick/laravel-cf-workersai)
- **Vision** works on 7 models. Send base64 data URIs; Llama 4 Scout rejects HTTP URLs. **Logprobs** are only on the newer OpenAI-shape models (0–20 `top_logprobs`). **Context** ranges from 3.5k to 1.3M tokens per model. — per-model JSON in [cloudflare-docs](https://github.com/cloudflare/cloudflare-docs/tree/production/src/content/workers-ai-models)
- **Reasoning control and output are inconsistent.** Control is through `reasoning_effort` with per-model allowed values, or `chat_template_kwargs`. The docs conflict on Kimi K2.6: the changelog says `thinking`, the model schema says `enable_thinking`. GPT-OSS uses `reasoning.effort` and can't be disabled. Output appears in `reasoning`, `reasoning_content`, or inline `<think>` tags. — [Kimi K2.6 changelog](https://developers.cloudflare.com/changelog/post/2026-04-20-kimi-k2-6-workers-ai/)
- **Always send max tokens.** Legacy models default `max_tokens` to 256, and `/v1` reportedly caps at 256 when it's omitted.
- **Known streaming bug (open, Sept 2026):** on Llama 3.3 70B via `/v1`, `delta.content` sometimes arrives as a JSON number (e.g. `6`), which drops characters. — [cloudflare/ai#651](https://github.com/cloudflare/ai/issues/651)
- **Pricing:** $0.011 per 1,000 Neurons. There's a free 10,000 Neurons/day on both Free and Paid plans, which is roughly 50k–1.8M tokens depending on the model. Workers Paid is $5/month. Seven frontier models (Kimi K2.6/K2.7, GLM 5.2/5.3/5.3 Flash, DeepSeek V4) are paid-only. — [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)
- **Rate limits:** text generation is 300 rpm per task type. Paid-only models are **20 rpm** per account per model, or 50 rpm with AI Gateway credits. HTTP 429 has three meanings: 3021 is the per-minute rate limit (retry; observed in the live test), 3036 is the daily free quota (don't retry) and 3040 is out of capacity (retry). — [limits](https://developers.cloudflare.com/workers-ai/platform/limits/)

## Open Questions / Gaps

- **Research wasn't tested live.** api.cloudflare.com, developers.cloudflare.com, community.cloudflare.com and docs.litellm.ai were blocked by the session's proxy. Docs were read from the `cloudflare/cloudflare-docs` GitHub source and Tavily extracts. A later live test covered Connect validation, errors through LiteLLM and rate limits; see [live test findings](../../../live_test_findings.md). Still inferred: the response for a token lacking Workers AI permission on `/ai/models/search`.
- Whether `/v1/chat/completions` correctly translates the OpenAI `response_format` envelope, `tools`, and `image_url` parts for legacy-schema models (Llama 3.x/4, GPT-OSS, Mistral, Qwen) is undocumented. It needs Kiln's per-model tests.
- Whether `/v1` rejects or ignores OpenAI params a legacy model doesn't declare (e.g. `stream_options`, `parallel_tool_calls`, `logprobs`).
- Kimi K2.6 thinking control: the docs conflict between `chat_template_kwargs.thinking` and `enable_thinking`.
- Whether the Cloudflare-wide API limit (1,200 requests / 5 min per user) applies to Workers AI inference.
- Whether GPT-OSS on `/v1/chat/completions` returns reasoning, and in which field.
- LiteLLM 1.90.1–1.90.7 patch releases weren't checked for the rewrite. 1.91.0 is the first minor release confirmed to have it.
