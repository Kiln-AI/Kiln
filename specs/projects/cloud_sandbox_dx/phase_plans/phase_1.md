# Phase 1: uv Floor and Python 3.13 Pin

## Overview

The foundation every later phase assumes. Two small, independent changes.

`pyproject.toml` uses `exclude-newer = "7 days"`, a relative form that uv < 0.10.0
cannot parse. A too-old uv does not fail on it — it ignores the setting, re-resolves
the whole dependency graph on every `uv run`, rewrites `uv.lock`, and installs a
broken fastapi/starlette pair. `required-version = ">=0.10"` converts that silent
corruption into a loud refusal at the point of use (F2).

Separately, the environment is built on uv-managed CPython 3.13 rather than the
sandbox's system Python 3.11, whose build has no `tkinter` (F3). The choice is
carried by a `.python-version` file, which uv consults on every later sync so the
pin survives deleting `.venv`. That file is generated by `setup_env.sh` in Phase 2,
so this phase only has to make sure it is never committed.

## Steps

1. `pyproject.toml` — add `required-version = ">=0.10"` as the first key of the
   existing `[tool.uv]` table, above the unchanged `exclude-newer`:

   ```toml
   [tool.uv]
   required-version = ">=0.10"
   exclude-newer = "7 days"
   ```

2. `.gitignore` — add `.python-version`, beside the existing `.mcp.json` entry.
   Both are generated files in the same spirit, and F3 deliberately avoids adding a
   tracked top-level file.

No source changes for `tkinter`: the imports in `desktop_server.py` and
`import_api.py` stay exactly as they are, because a 3.13 venv makes them work (F3).

## Tests

Config-only; no unit tests. Verified behaviorally:

- `uv run python -c "print(1)"` succeeds and leaves `uv.lock` byte-identical
  (md5 before/after), proving `required-version` is valid syntax for the installed
  uv and that `exclude-newer` is now honored rather than re-resolved.
- `uv run python -c "import tkinter"` succeeds on the 3.13 venv.
- `git status --porcelain` stays empty with `.python-version` present on disk,
  proving the ignore entry works.
- `required-version` is a new hard gate for CI, so its blast radius was checked:
  all ten workflows use `astral-sh/setup-uv@v3` with no `version:` input, which
  installs the latest uv, so none of them can land below the floor. Worth
  re-confirming on the PR run.
- `uv run ./checks.sh --agent-mode` green.
